Capture First · 新建日程设计稿 v2

新建日程不是配置表单，是一次带默认值的快速落位。 按 Ctrl+N 打开，光标已在输入框，打标题按 Enter 就完成 —— 默认「今天 · 下一个整点 + 1 小时」，想改才展开。 编辑已有日程走右侧 380px inspector（字段即存，无保存按钮）。

v2 依据：4 份独立评审 + 滴答清单实机对照。分组改为顶部时间 / 中部输入 / 底部归属， 补回跨天、错误态、提交失败，删除域模型里不存在的「重复 / 提醒 / 优先级」。

时长

  • 标题在上、时间在下。这是 Google / Apple / Notion / Linear / Things 的顺序；九家竞品里只有滴答把时间放在最上面。v1 曾照滴答做，K 的实机截图取证后改回主流顺序。
  • 分组是「标题 → 时间 → 归属」。v1 把时间塞进图标行、清单塞进 ⋯，分组逻辑借鉴错了对象。
  • 输入区 88px 高（3 行）。v1 只有一行，写不下稍长一点的标题。
  • 清单常驻底部，不是藏进 ⋯ —— 它和"这条归哪"是一体的。
  • 「新建」而不是「添加」：本应用新建日程一律叫「新建日程」（shell:topBar.newEvent），"添加"是任务的动作。
  • 没有「准备做什么？」：这是任务的问句。日程用可见标签「标题」+ 占位示例。
  • 删掉了「重复 / 提醒 / 优先级」：CalendarEvent 域模型里没有这些字段，画了等于承诺做不到的功能。

时长

  • 跨天自动标记「+1 天」。结束时间 ≤ 开始时间时，结束自动落到次日，chip 显示 今天 · 23:00 – 01:00。v1 只有日期 + 两个时间框、没有结束日期，跨天在设计上就做不到。
  • 时间错误提示在时间行正下方（离操作源 0px），不是卡片底部。
  • 「全天」是时长的一种，不是独立开关 —— 选它时时间行整体换成「今天 · 全天（1 天）」，时间输入消失而非变灰。
  • 时长芯片 30 分 / 1 小时 / 2 小时：比"改结束时间"快，也是竞品通行做法。
