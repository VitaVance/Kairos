# Kairos v2 — 这一版里必须保留的东西

> 给后续任何一轮改稿的人（包括我）。改之前先读这张表。
> 每一条都写明：**保什么、为什么它是对的、什么情况下才可以动。**

---

## A. 已经验证过的设计决策（不要重新讨论）

### A1 底部视图切换胶囊：回到 surface 阶梯

**保留**：`.tl-pill` 用 `surface + border-strong + shadow-lg`，选中态 `accent 12% → surface`。

**为什么**：上一版是固定深色板，六个组合的对比跨度 1.09 → 12.49，同一控件在浅色下像外来黑板、
深色下沉进地面。现在六个组合全部落在 1.08–1.38 的可辨认区间。

**只有这些情况可以动**：令牌本身改了（那要先改 `tokens.css`）。

### A2 CTA 用 `--tl-cta-bg` / `--tl-cta-text`，不用 `--tl-accent`

**保留**。`--tl-accent` 配白字在 refined/light 是 **3.68:1**，不合格。
cta 那对令牌是专门为这个按钮建的，六组合 4.79–6.19。

### A3 禁用态是颜色，不是淡出

**保留**：`opacity: 1` + `--bg-sunken` 地面 + `--ink-2` 墨。

**为什么**：`.tl-btn:disabled` 的 `opacity: .5` 把主按钮压到 **2.14:1**。
§5.1 原文就是「禁用是颜色，不是淡出」。这条在 ADR 0004 的实施里已按例外处理并记入 §8.13。

### A4 选中态用 1px `-ink` 实心边，不是半透明环

**保留**：象限 chip、分段控件、胶囊选中项，一律 `border: 1px solid <hue>-ink`。

**为什么**：
- `box-shadow` 在 Windows 强制色模式（高对比度）下**整个消失**，状态指示没了；
- 半透明环的对比只有 1.28–1.52，远低于 1.4.11 的 3:1；
- `-ink` 边实测 5.06–6.96，六组合全过。

**不要**因为「环看起来更轻」就换回去。轻是代价，不是优点。

### A5 六个组合逐个实测，不靠目测

**保留这个习惯**。任何新语义色、新边界、新状态，都要在 refined/protool/editorial × light/dark
六格里算出数字。这一版里所有「看起来还行」的判断，事后都至少错了一次。

## B. 这一版的视觉语言（新片段必须沿用）

### B1 三层结构：rail(56) + sidebar(220) + main

顶部一条 hairline，卡片 `--radius-xl`，浮层 `--radius-lg`，控件 `--radius-md`。
不要发明第四种圆角或第二种阴影。

### B2 象限色只出现在两处

色点（6px 圆）和选中块的底 + 边。**不铺满**——四种颜色同时铺开就是交通灯，反而看不出选中。

### B3 时间阶梯标签是这一版的核心视觉

六档必须一眼可分：

| 档 | 靠什么区分 |
|---|---|
| `month` | 「下个月」措辞，**永不出现具体日子** |
| `week` | 「这周」措辞 |
| `day` | 「周五」「今天」 |
| `period` | 「今天下午」（日期 + 时段，无时刻） |
| `time` | 「今天 18:00」（带冒号） |
| `none` | 清单名（不是日期） |

**不要**把它们都渲染成同一种灰色小字。如果用户分不出「下个月」和「11月30日」，
整个 ADR 的精度主张就白写了。

### B4 逾期有两种，颜色不同

- `day` / `period` / `time` 逾期 → `--danger-ink`（真的迟了）
- `week` / `month` 窗口过去 → `--warning-ink` + 「上周·未完成」（只是窗口过了，不是迟到）

**永远不要**把 week/month 标成红色。这是 ADR §2 的核心。

### B5 图标：Lucide 几何，`currentColor`，`aria-hidden`

24×24 网格，`fill: none`，描边随尺寸（14→1.9 / 16→1.8 / 18→1.7 / ≥24→1.6）。
**不手绘**。仓库里手绘齿轮失败过两次。

## C. 交互约定（不能因为「简化」而删掉）

### C1 棋盘/列表的勾选

勾掉 → 行进入「已完成」折叠，计数器更新，**不消失**。
日历上则**不再显示**（日历记安排，清单记完成）。

### C2 键盘：每一组单选一个 Tab 停点

`role="radiogroup"` + roving tabindex + 方向键 + Home/End。
全组 `tabIndex=0` 是错误——用户要按四次 Tab 才能越过一组。

### C3 破坏性操作

原生 `<dialog>` + `showModal()`，焦点落在**安全动作**，破坏性按钮在右侧末尾且有 600ms 迟滞。
不做内联两段式确认（仓库里因此清空过一次数据）。

### C4 捕获条：没有类型开关

Ctrl+N 打开就能打字，不选「任务/日程」。时间可以之后再定，默认「不限」也不算错。

### C5 非模态面板

日历空槽点击弹出的小条**不用 `<dialog>`**：背后的网格要保持可交互，点外面就关。

## D. 指南层面的硬要求（modern-web-guidance）

### D1 触摸目标

- 鼠标：最小 24×24（WCAG 2.5.8）
- 触摸：最小 44×44（WCAG 2.5.5）
- 图标按钮用伪元素扩热区，**视觉尺寸不变**

已在 `shared.css` 的 `--target-size` 里实现。新控件自动继承 `:where(button, ...)`。

### D2 组件该看容器，不该看视口

**这是当前 03 月视图的一个已知问题**：底部胶囊用
`inset-inline-start: calc((100vw + 276px) / 2)` 把自己钉在内容区正中——
`276px` 是侧栏 + rail 宽度写死的。窗口一变、侧栏收起、或换成 `--wide` 布局，它就错位。

正确做法：给 `.main` 设 `container-type: inline-size`，胶囊用 `@container` 或
直接在 `.main` 里用 `position: absolute; inset-inline: 0; display: flex; justify-content: center`。
**组件不该知道侧栏有多宽。**

`form-factor-adaptation` 原文：「Use container queries instead of viewport-width media queries
for component layout, so a component adapts wherever it is placed.」

### D3 固定条不遮内容

底部固定条会盖住滚到底的内容，也会盖住聚焦的元素（WCAG 2.4.11）。
滚动容器要设 `scroll-padding-block-end` ≥ 条高。已加。

### D4 文字排版

- 标题 `text-wrap: balance`，正文 `text-wrap: pretty`
- **不要**用在 `*` 上（有布局开销，balance 只对短块有效）
- 长串 `overflow-wrap: break-word`；只在链接/代码上用 `anywhere`

### D5 图标按钮必须有可访问名

`aria-label` 或视觉隐藏文字；装饰性图标 `aria-hidden="true"`。

## E. 什么情况下才可以推翻以上

只有三种：

1. **令牌变了**（先改 `tokens.css`，再改稿）
2. **ADR 改了**（决策级变更，写新的 ADR 而不是偷偷改稿）
3. **实测数字变了**（拿新的六组合数据说话，不是「我觉得更好看」）

其余一切「我觉得这样更简洁」都不构成理由。
这一版的价值恰恰来自那些**看起来多余、但每条都有实测支撑**的约束。

## F. 看起来不一致、但其实是对的（别「修」它）

### F1 日程视图里，`day` 档的行不显示日期

在四象限板和清单里，「交房租」显示「后天」；在日程视图里它**没有**时间标签。
这不是漏了——日程视图按日期分组，分组头已经写着「周六 28」，
行上再写一次「后天」就是重复（同一句话在一屏里说两遍）。

判断标准：**那一栏的信息是不是已经被上层说了。** 说了就不重复，没说到才补。

### F2 列表用「粗窗口在前」，日程用「时间先后」

清单把「下个月」排在最前（粗窗口容易被忘、没有提醒兜底）；日程视图严格按时刻排。
两者相反，是对的——它们回答不同的问题：清单问「该做哪个」，日程问「什么时候」。

### F3 同一条「这周」的事，在四个地方形态不同

| 位置 | 形态 | 为什么 |
|---|---|---|
| 板 / 清单的行 | 「这周」小标签 | 行是密集列表，只放得下一个词 |
| 月 / 周视图 | 一条横跨区间的连续带 | 区间在网格上就该是连续形状 |
| 日程视图 | 一行，右侧补「11/23 → 11/30」 | 一行就是一行，但要能看出它覆盖多久 |
| 详情面板 | 完整区间 + 可改 | 这里是编辑，要说全 |

四个形态，同一个事实。**判断一致性的标准不是「长得一样」，是「说的是同一件事」。**

### F4 深色截图不代表文件是深色

`base.js` 用 `sessionStorage` 记住评审时选的皮肤/主题（同一标签页内跨片段保持）。
新开标签页会回到文件自己声明的 `data-skin` / `data-theme`（一律 refined / light）。
截图前若不确定，先看 `<body>` 上的声明，别凭截图判断。
