检查更新 · 面板设计稿 v1

这个面板只做一件事：告诉用户要不要更新，并给出唯一的下一步。 所以它被压到 400px —— 一条状态、一行版本、一个按钮，其余删掉。 关闭退成 28px 的安静图标；免责说明限宽成一句脚注；结果与动作之间用一条发丝线分开， 动作固定在卡片底部，六种状态里位置不变。 所有颜色只消费 tokens.css，对比度用脚本逐对实算（见 07）。 顺带记下一条实算出的现状缺陷：遮罩在两种深色组合里比面板本身还亮（07 末条）。

尺寸与文案依据：UpdatePanel.tsx / update-panel.css 现状、docs/DESIGN-LANGUAGE.md §2.3 / §5.4、docs/UI-AUDIT.md §G。

01 初始态 · 还没检查 可交互：点「检查更新」走完 idle → checking → 结果

下一次检查的结果：

检查更新

状态就绪。点下面的「检查更新」。

  • 400px，不是 520。内容最多是「一句状态 + 一行版本 + 一个按钮」；520 宽会让卡片右半边常年空着。400 也与应用里 380px 的 TaskDetailPanel 同一尺度。
  • 没有可见标题。入口按钮已经叫「检查更新」，再做一个 17px 标题等于同一句话出现两次。对话框的无障碍名由隐藏的 h2 提供。
  • 关闭是 28px 的安静图标（16px 线、--ink-3、无底色），hover 才出现极浅底。现状的 44px 方块在视觉上和主按钮同重。
  • 初始态只给「当前版本」。「尚未检查」这类句子是噪音：卡片刚打开、还没结果，本身就是未检查的证据。
  • 免责声明降为脚注，12px、限宽 17rem、与按钮同一栏。它是一句旁注，不该和状态并列成一段正文。
  • 动作固定在底栏，与内容之间一条 --hairline-soft。六种状态里按钮都在同一个位置。
  • 弹层用原生 <dialog> 呈现（Esc 关闭、焦点陷阱、关闭后焦点回到侧栏刷新按钮），本稿只 styling 面。

02 检查中 · 进度感但不假装百分比 动作栏整栏消失

检查更新

正在检查…

  • 不显示假百分比。HTTP 请求没有可用的进度；写 60% 是编的。2px 的不确定条只表达「在动」。
  • 检查中整栏动作消失，而不是留一个禁用的主按钮。一个按不动的按钮在忙态里只会制造「是不是卡住了」的疑问；关闭仍在右上角，随时可以走。
  • 只动 transform。条本身是一个 32% 宽的色段，在轨道里平移。
  • prefers-reduced-motion: reduce 下整条进度条隐藏，只留「正在检查…」—— 一个停在起点的条比没有条更误导。文字本身就在 live region 里，状态照样被播报。
  • 检查落地后结果直接替换这一块，不做高度过渡：状态变了就是变了，动画只会拖慢阅读。
  • live region 上不放 aria-busy。aria-busy="true" 会让辅助技术推迟播报整块内容 —— 而「正在检查…」恰恰是要播报的那句话。忙态标记挂在进度条本身。

03 已是最新 · 给结论，不给两行相同版本号 零主按钮

检查更新

已是最新版本

当前 0.1.0

  • 「已是最新版本」必须留。界面只摆一个「0.1.0」无法区分「刚查过、没有新版」和「还没查」；结论句是这次检查确实发生过的证据。
  • 但它是一行结论，不是版本表下面的尾巴。结论在上（14px/600/成功绿），版本退成 13px 的副行，「当前 0.1.0」而不是「当前版本 0.1.0」。
  • 只显示一个版本号。没有新版时，把「当前 0.1.0」和「清单 0.1.0」并排只会让人找不同。
  • 没有任何主按钮。这个状态没有「下一步」；「再次检查」是次要动作，用 ghost 放在右端。
  • 旧文案「清单版本」是开发者词（manifest），本稿一律不出现。

04 有新版本 · 版本对比 + 一个真按钮 不是一句「请从发布页下载」

检查更新

有新版本可用

0.1.0 → 0.2.0

修复了周视图在跨周拖动时的定位偏移；新增日程提醒的提前量设置；启动速度提升约 30%。

  • 给按钮，不给说明书。「请从发布页下载并覆盖安装」要求用户复制一个 URL、找浏览器、再理解覆盖安装；这里是一个「前往下载」，点了用系统浏览器打开发布页。
  • 为什么不是「自动下载」。UpdateChecker 端口只有 fetchManifest 和 openReleasePage，没有安装方法。画一个自动下载就是在承诺代码做不到的事。将来端口补齐后，同一个位置换成「下载并安装」+ 确定进度条，骨架不动。
  • 版本对比是一行箭头。0.1.0 → 0.2.0：旧号小、灰；箭头更灰；新号 17px/600、tabular 数字。比两行 dl 快一眼。
  • 「有新版本」是整个面板唯一用强调色的标题，也是唯一的主按钮。其余状态要么零主按钮，要么主按钮是「重试」。
  • 更新说明限 3 行；更长的内容在发布页看，不在对话框里展开。
  • 清单里没有发布页时：主按钮不出现，说明改为「稍后重试」，版本对比保留 —— 不给一个点了没反应的按钮。

05 检查失败 · 说清代价，给重试 错误用 -ink 令牌

检查更新

检查失败

没能连接到更新服务，请检查网络后重试。

  • 主按钮变成「重试」，而不是继续显示「检查更新」。失败后同一个词会被读成「我刚才是不是没点上」。
  • 一句话说清发生了什么 + 下一步；不带 HTTP 状态码、不带异常文本。
  • 四种失败各有各的话，共用一个骨架：网络不可达 → 检查网络；返回内容无法识别 → 「更新服务返回的内容无法识别，请稍后再试」；源为空 / 格式不对 → 「此版本无法在线检查更新」。都落在同一张卡里。
  • 颜色用 --danger-ink，不是 --danger。原始色相作正文只有 3.1–3.6:1，docs/UI-AUDIT.md §G 记过这条；本稿的失败标题、图标都走 -ink。
  • 错误没有造成任何数据损失，所以不需要二次确认：重试是安全的，直接做。

06 浏览器中不可用 · 兜底帧 正式发布时入口直接隐藏

检查更新

在此环境中不可用

你正在浏览器中打开，这里连接不到应用的更新服务。桌面版可以正常检查更新。

  • 正式发布里，这个入口直接不渲染。一个点了只会解释「我不可用」的按钮，比没有按钮更糟 —— 它消耗一次点击、一次注意力，什么也没换来。侧栏的刷新图标在浏览器构建中隐藏。
  • 这一帧仍然要画：它是 checker === null 时的内部兜底（例如构建时漏配了更新地址、插件加载失败），此时入口可能已经出现，必须有一个说得通的落点。
  • 文案对用户说话，不对开发者。没有「dev 模式 / 浏览器环境 / tauri / 更新源配置」，只有「浏览器里连不到更新服务，桌面版可以」。
  • 没有假动作。这个环境里没有可用的 openReleasePage，所以不给「下载桌面版」按钮 —— 不给点了没反应的按钮。
  • 没有「在线 / 离线」二选一。那是给气隙部署留的后门，不是用户的决策；构建决定用哪条路。
